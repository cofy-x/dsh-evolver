# 架构与方向

[English](architecture.md) | [简体中文](architecture.zh.md) | [文档地图](README.zh.md)

Evolver 拥有提案生命周期和有界诊断证据。DSH 拥有 Agent、canonical Session、模型执行、工具、命令、凭据和权限。集成仅使用公开服务与事件；禁止引用 Harness 私有源码或无留痕修改请求。

## 生命周期

```text
工具失败 → 脱敏观察 → 精确模式 → 预留代次
→ 提案 → 验证 → 人工接受 → 晋升
→ 后续 Session 留痕指导 → 有界评估 → 人工保留/回滚
```

采集器观察与 Agent 关联的最终 `tools/result` 事件。提案始于 `evaluating`，验证产生 `pending` 或 `rejected`。只有验证通过的 pending 提案可被接受，只有 accepted 提案可被晋升，回滚将 promoted 指导标记为 superseded。重复相同转换是幂等的。验证不代替人工批准。当前提案器与结构性验证器都是确定性、离线实现。

模式是工具名、错误码和规范化脱敏摘要的版本化精确签名，不是语义匹配。观察保留独立来源；每代提案链接到准入时的 occurrence。同一模式已有活跃代次时不能再生成；拒绝或取代后，必须新增配置数量的匹配失败才能重新准入；不同代次不共享评估队列。

准入先在锁内事务预留所有权，在锁外调用提供方，再仅在相同 reservation 仍有效时提交。失败会放弃所有权但不丢失 occurrence。后续 occurrence 可回收过期租约；迟到结果关闭式拒绝。过期不等于取消提供方。

## 持久化与隐私

默认事实源为 `$DSH_HOME/evolver/audit-v1.jsonl`，其目录可由 `dataDir` 覆盖。变更先获取 DSH 文件锁，重放并验证完整事件流，追加序号单调递增的事实，再原子替换仅所有者可读写的文件。新写入和重启重放使用同一 codec 与生命周期不变量。损坏流、无效引用或转换均关闭式失败；支持的旧事件无需重写历史即可读取。

审计保留有界脱敏失败摘要、标识符、提案/验证事实、结果元数据与曝光记录，不保留完整 Session 事件、推理、工具参数、凭据、成功值或完整输出。不处于采集窗口内的成功结果会被丢弃。脱敏覆盖常见凭据、URL 和 home 路径形式，但不是通用敏感数据分类器。

所有 Cordis 注册均由 effect 管理。dispose 移除贡献、停止新变更准入，并等待已准入的提供方/持久化工作。观察、提案或共享文本都不能执行命令、编辑源码或修改评估器、验证器、审批与安全策略。

## 指导与评估

晋升前不增加模型 token，也不改变工具 schema。后续 `agent/session-start` 通过 `agent.inject()` 将有界数量的已晋升策略合为一条插件来源的 instruction。DSH 在模型使用前将其提交到 canonical Session 历史。回滚停止未来注入，不改写已有 Session。

晋升以触发观察的审计边界冻结有界 baseline。Treatment 仅包含具有曝光记录的 Session 中匹配工具的结果。结果以 `(sessionId, callId)` 标识；代次通过审计序号而非时间戳巧合分隔。无模式关联的旧提案保留原 baseline 语义。

两组样本充足后，失败率差产生 `improved`、`regressed` 或 `neutral`；否则为 `insufficient`。窗口填满即停止。这是描述性运行信号，不是任务有效性的因果或统计显著证据，也不会自动改变生命周期。任务级比较使用独立的[配对 benchmark](paired-benchmark.zh.md)。

## 未来优先级与扩展门禁

首先建立策略价值证据：固定诊断模板尚无任务成功率增益证明。未来实验需要有区分度的任务、冻结候选、独立评分及完整保留失败；单纯增加 LLM 提案器不能弥补证据缺口。

外部提案或验证提供方必须具备有界候选/证据契约、deadline、协作取消、迟到结果隔离和 dispose 预算。当前永不结束的提供方会无限延迟 dispose。自动化与 UI 可以调用公开生命周期操作，但不能绕过人工审查或接管 DSH 服务。代码演进和网络共享尚未实现。

每个数据目录只运行一个活跃 runtime。文件锁串行化写入，但同步读取是进程内快照，在下次事务才刷新。多 runtime 需要查询与注入边界的明确新鲜度契约。曝光持久化在同步注入后异步执行，两套存储不共享原子事务。只有建立协调且可等待的边界后，才能声称崩溃一致的测量。

整日志重放/替换与无界失败历史仅适用于实验规模。选择压缩或 SQLite 前，应先测量日志增长、变更延迟与查询需求。提供方和消费者共同发布期间保持单包，只有出现独立生命周期或分发需求才拆包。
